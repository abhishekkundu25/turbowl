# Version 1: a fast Rust OWL 2 RL reasoner

Status: in progress. Tickets: `docs/tickets/v1/`. Decisions: `docs/adr/`
(ADR 0004 sets the target). Words: `CONTEXT.md`. Background:
`docs/research/reasonable-parity.md` (what `reasonable` does, at
`fecee2b`), turtle-lsp's `docs/research/reasoner-sota-2026-11.md` (the
field).

## Problem Statement

People who want OWL 2 RL reasoning in an editor, a browser, a Rust or Python
program, or (later) Protégé have no open, actively developed engine that is
fast, embeddable, builds for WebAssembly, and keeps its results current as
data changes. `reasonable` comes closest: Rust, OWL 2 RL, diagnostics,
Python bindings. But it implements part of OWL 2 RL, it has bugs that
change results, it throws away all state on any deletion, and it is
verified by hand-picked unit tests only. It is no longer slow on Brick: its
README's 2023 log (version 0.2.6) shows 18.7 s for Brick plus a small model,
but version 0.5.0-a1 reasons over the same input in about 13 ms here, so it
is a demanding speed baseline.

## Solution

A new reasoner, in Rust, in its own repository, whose goal is speed. It
computes the closure the W3C OWL 2 RL rule tables define, for the rules
listed below, and is judged by independent oracles that implement those
tables, not by any one reasoner. It is built for speed from the start (term
ids, sorted relations, semi-naive evaluation, `owl:sameAs` by
representatives). `reasonable` and Nemo are the speed baselines. Version 1
is the baseline for a series of measured experiments
(`docs/specs/experiments.md`).

## The rule set of version 1

Named as in the W3C OWL 2 RL tables (OWL 2 Profiles, section 4.3).

- **Equality:** eq-sym, eq-trans, eq-rep-s, eq-rep-p, eq-rep-o.
- **Properties:** prp-dom, prp-rng, prp-fp, prp-ifp, prp-symp, prp-trp,
  prp-spo1, prp-spo2 (chains of any length; cyclic lists terminate),
  prp-eqp1, prp-eqp2, prp-inv1, prp-inv2.
- **Classes:** cls-thing, cls-nothing1, cls-int1, cls-int2, cls-uni,
  cls-svf1, cls-svf2, cls-avf, cls-hv1, cls-hv2, cax-sco, cax-eqc1,
  cax-eqc2.
- **Schema:** scm-sco, scm-eqc1.
- **Inconsistencies, reported as diagnostics:** cax-dw, prp-pdw,
  cls-nothing2, prp-asyp, prp-irp, cls-com, and dt-not-type for the
  datatypes listed in `rules/datatype.rs` (a literal not in its datatype's
  value space, including one typed by prp-rng).

Every list (`owl:intersectionOf`, `owl:unionOf`,
`owl:propertyChainAxiom`) of a class or property is read, structurally, and
lists derived during the run count. A list is read in the W3C `LIST[...]`
form: along a path of `rdf:rest` from its head to `rdf:nil` on which every
cell has an `rdf:first`; `rdf:rest` stops at `rdf:nil`, which is never a
later cell (it can be a head). Rules not listed (eq-ref, eq-diff*,
prp-key, cls-maxc*, the rest of scm-*, dt-type*, dt-eq, dt-diff) come after
version 1, as experiments.

## User Stories

Reasoning
1. As a modeller, I want to load Turtle, N-Triples, N3 and RDF/XML files and get the OWL 2 RL closure, so that I see what my model implies.
2. As a modeller, I want each rule to give exactly the inferences the W3C tables define, so that results are standard.
3. As a modeller, I want `owl:sameAs` handled without the closure blowing up, so that models with many aliases stay fast.
4. As a modeller, I want property chains, inverse, symmetric and transitive properties, domains and ranges, so that property axioms take effect.
5. As a modeller, I want class intersections, unions, someValuesFrom, allValuesFrom and hasValue, so that class definitions classify my data.
6. As a modeller, I want blank nodes in different files kept apart, so that unrelated `_:b` nodes are not merged.
7. As a modeller, I want language tags kept on output, so that my labels survive a round trip.

Diagnostics
8. As a modeller, I want an individual in two disjoint classes reported, so that I find contradictions.
9. As a modeller, I want disjoint properties, asymmetric and irreflexive properties, members of `owl:Nothing` and `owl:complementOf` violations reported, so that every inconsistency the rule set defines is found.
10. As a modeller, I want ill-typed literals reported, including literals outside a property's datatype range, and only those, so that data errors show without false alarms.
11. As a tool author, I want each diagnostic to carry its code, rule, severity, message and the terms involved, so that I can link it to the data.

Incremental
12. As an editor author, I want to add triples and run again without starting over, so that keystrokes stay cheap.
13. As an editor author, I want removing triples to give the right closure, so that deleted facts stop implying things.
14. As an editor author, I want an unchanged graph to cost nothing when I set it again, so that a refresh is free.

Interfaces
15. As a Rust developer, I want a small library interface (load, insert, remove, run, triples, diagnostics, write), so that embedding takes minutes.
16. As a command-line user, I want to reason over files and get the closure, the inferred triples only, or diagnostics as text or JSON, with exit codes I can script against.
17. As a Python user, I want a reasoner that takes and returns rdflib graphs and terms, so that my notebooks can use it.
18. As a browser developer, I want the core to build for `wasm32-unknown-unknown`, so that turtle-lsp can embed it later.

Verification and performance
19. As a maintainer, I want every closure checked against Nemo, OWL-RL, the W3C tests, a DL reasoner and a reference evaluator, so that correctness does not rest on one implementation.
20. As a maintainer, I want generated inputs checked against the reference evaluator with a replayable seed, so that rare cases are found.
21. As a maintainer, I want a benchmark that runs this reasoner, `reasonable` and Nemo on the same inputs and records times and memory, so that speed claims carry numbers.
22. As a maintainer, I want every verification run stored in the repository with its date, inputs, versions and results, so that results can be audited and compared later.
23. As a future agent, I want one entry point (`AGENTS.md`) that says how to build, test, verify and continue, so that I can pick the work up cold.

## Implementation Decisions

- **One deep module.** The core crate's public interface is the `Reasoner`
  (create; load a document; insert or remove triples; set the base triples;
  run; iterate the closure or only inferred triples; read diagnostics;
  write a document). Terms in and out are `oxrdf` types. Term ids, the
  dictionary, relations, the engine and the rule families are internal.
  Every adapter (CLI, Python, the oracle tests, the benchmark) uses only
  this interface. There is one rule set, so there is no profile type.
- **Term ids and the dictionary.** Every term is interned to a `u32`. Blank
  nodes are scoped per document. Literals keep their datatype and language
  tag.
- **Input and output** use Oxigraph's parsers and serializers (`oxttl`,
  `oxrdfxml`, `oxrdf`): Turtle, N-Triples, N3 and RDF/XML in and out.
  Statements of N3 that are not RDF are dropped and counted.
- **Engine** (ADR 0001): sorted, duplicate-free relations of term ids;
  semi-naive rounds with stable, recent and to-add parts; merge join,
  antijoin and leapjoin; predicate tables for the vocabulary the rules use.
- **Rules** are Rust code, one module per rule family, registered in one
  table, implementing the rule set above.
- **Equality** (ADR 0003): union-find representatives inside; output
  expands them.
- **Incremental runs**: additions are joined semi-naively against the
  stored closure. Any removal re-runs from the remaining base triples, and
  setting an unchanged base costs nothing. Better deletion is an
  experiment.
- **Generalized triples inside**: the rules run over generalized triples
  (any term in any position), as the W3C rule tables and Nemo do: a
  literal joins like any other term, eq-* included, and a literal typed
  by prp-rng feeds dt-not-type. Only the closure the interface returns
  leaves out triples that are not RDF (a literal subject, or a predicate
  that is not an IRI).
- **Datatypes**: dt-not-type checks xsd:string, xsd:integer, xsd:int,
  rdf:langString and rdf:XMLLiteral; a literal of another datatype is
  never reported. More datatypes are an experiment.

## Testing Decisions

- **The interface is the test surface.** Every suite drives the `Reasoner`
  (or the CLI, or Python) and compares closures and diagnostics as sets.
  Unit tests inside the engine are the exception: the engine has its own
  internal seam and its own comparison with a naive evaluator.
- **Oracle suite** (`crates/oracle`, ADR 0004):
  - **Nemo** with `oracles/nemo/owl2rl.rls` (the W3C forms of exactly the
    rule set above): closure and findings equal, on every input. Nemo has
    no datatype checks, so dt-not-type is judged by OWL-RL, the W3C tests
    and the reference evaluator.
  - **OWL-RL** through `uv run` in a project-local environment: our
    closure is contained in OWL-RL's (it implements more rules and adds
    axiomatic triples), apart from the listed OWL-RL faults.
  - **The W3C tests**: the OWL 2 RL test cases and the RDF 1.1 Semantics
    entailment tests. Every test Nemo passes, this project passes; the
    others are listed by name with the missing rule.
  - **HermiT** (pinned, on a fetched JRE): entails every inferred class and
    property subsumption.
  - Inputs: the minimal case per rule and per diagnostic, Brick and the
    building models (fetched into `data/`), and the W3C archives. Tools
    are pinned under `tools/` (fetched by `scripts/fetch-tools.sh`). An
    oracle that is not installed is reported as skipped; with `CI=true` it
    fails.
- **Oracle faults** are the only filters: each has an id (`F1`...), a
  test showing the other oracles agree with this project, and a filter
  that removes exactly the affected triples or findings. The list lives in
  `crates/oracle/src/differences.rs`.
- **Rule tests**: one minimal input per rule and per diagnostic, with the
  expected inferences written out.
- **Chaos** (as turtle-lsp's `tests/chaos.rs`): generated ontologies and
  data from a seed, compared with the reference evaluator; `CHAOS_SEED`,
  `CHAOS_ITERS` and `CHAOS_ONLY` replay a case; a failure saves the input.
  The reference evaluator is itself compared with Nemo on generated inputs.
- **Incremental**: for generated inputs, every split into batches of
  additions, and every removal, gives the same closure as one full run.
- **Scaling**: every operation that should grow linearly with its input
  (or with its output, where the output is the measure) has a
  `scaling_*` test. It times the operation at sizes spanning at least 16×
  (the fastest of several runs per size), fits the growth exponent on a
  log-log scale, and fails above 1.25: an n log n sort passes, a
  quadratic blow-up (exponent 2) fails. An operation that should not grow
  at all (one incremental addition against a larger base) fails above
  0.25. Where a structure's size can be counted (stored tuples,
  dictionary bytes), its growth is checked exactly instead of timed. A
  failure prints the table of sizes and times, and re-measures once
  before failing. A timed test keeps its sizes within one memory regime:
  crossing a cache level adds 0.2 to 0.4 to the exponent with no
  algorithmic cause, and the benchmark is where cache effects show. One
  operation is known not to be linear: a variable's duplicate check over
  many rounds of small scattered batches costs N·log²(N/b), the price of
  tiered sorted runs (as in datafrog). Its test counts comparisons and
  pins that class exactly; the regime real reasoning runs in (few rounds,
  large batches) is timed as linear. Experiment E10 (a filter per tier)
  would make it N log N.
- **Benchmark** (`crates/bench`): fixed scenarios (Brick variants, the
  building models, a generated LUBM-style university set at several sizes,
  an incremental edit stream, a sameAs clique), each run for this
  reasoner, for `reasonable` (linked in) and for Nemo (the pinned `nmo`
  with `owl2rl.rls`), recording median, spread, peak memory and the
  closure size; `--compare` diffs two result files.
- **Stored verification**: each full verification writes
  `docs/verification/<date>-<name>.md` (what ran, versions, counts, numbers,
  failures) and the raw results under `docs/verification/data/`.

## Principles

- **foundational-thinking, model-the-domain**: term ids, the dictionary and
  relations first; one rule table, one module per rule family.
- **type-system-discipline**: newtypes for term ids and predicates; no
  stringly typed rules.
- **boundary-discipline**: parsing, the CLI and Python validate; the engine
  and rules trust term ids.
- **exhaust-the-design-space**: the engine choice (ADR 0001) weighed three
  bases.
- **make-operations-idempotent**: loading the same document twice, setting
  the same base twice and running twice change nothing.
- **encode-lessons-in-structure**: every oracle fault is a filter with a
  test; every oracle runs in the suite, not by hand.
- **explain-the-number**: every benchmark number records its run count,
  spread and what bounds it.
- **separate-before-serializing-shared-state**: slices own disjoint files;
  the rule table is the one lock file, edited one line per rule family.

## Non-functional budgets (pass/fail)

Correctness:
- Nemo's closure and findings (dt-not-type aside) equal this project's on
  every input Nemo finishes in 10 minutes.
- This project's closure is contained in OWL-RL's on every input OWL-RL
  finishes in 10 minutes, after the oracle-fault filters.
- Every W3C test Nemo passes, this project passes; so do the dt-not-type
  tests within the checked datatypes (`xmlsch-02-whitespace-facet-2`,
  `datatypes-range-clash`), which Nemo cannot judge.
- HermiT entails every class and property subsumption inferred on Brick.
- 100,000 chaos iterations pass.

Performance (the goal):
- The full-run time is below `reasonable`'s on every benchmark scenario on
  this machine; the ratio is recorded. The ratio to Nemo is recorded too.
- Peak memory is below `reasonable`'s on every benchmark scenario.
- An incremental addition of one triple to Brick plus a building model costs
  under 10% of a full run.
- Every `scaling_*` test passes, and the benchmark's fitted time exponent
  for this reasoner over LUBM 1, 10 and 50 is at most 1.2 (recorded with
  the baselines' exponents).

Build:
- The core crate builds for `wasm32-unknown-unknown` with default features
  off.
- `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings` are
  clean.

## Out of Scope

- The OWL 2 RL rules not in the version 1 rule set: after version 1, as
  experiments.
- Compatibility with `reasonable`'s output conventions, CLI or Python API
  (ADR 0004).
- Deletion without a full re-run (DRed, counting, backward/forward): an
  experiment.
- Parallel rounds, columnar storage, worst-case-optimal joins: experiments.
- EL classification, a Protégé plugin, an OWL API adapter, turtle-lsp
  integration, a published WebAssembly package.
- Explanations (why a triple holds).
- Publishing (crates.io, PyPI, GitHub): only with the owner's approval.
