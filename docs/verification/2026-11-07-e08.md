# Verification: loop iteration 8, the base as pairs by predicate (2026-11-07)

The change: the base, the triples the reasoner holds for the whole session,
is one flat vector of each predicate's sorted (s, o) pairs with the
predicates and their starts, 8 bytes a triple instead of 12 (`b654de6`). A
load turns its parse buffer into the pairs in place; a full run copies each
predicate's pairs into its table. Snapshots move to format version 2. The
kept version before it is `f4fc0dd` (iteration 7); only records changed
between. The decision is iteration 8's row in `docs/specs/experiments.md`.

Raw results are in [`data/2026-11-07-e08/`](data/2026-11-07-e08/).

## Correctness

Every suite passed on the merged tree (`b654de6`): the core library (328

The all-cores median peak fell by 37.3 MB, and the middle halves are apart:
the change counts. One thread moved from 46.9 to 46.6 bytes per closure
triple (the implementer's 5 runs saw 2 MB more instead; one thread is about
unchanged). Reasoning on one thread fell 3 to 4% on the LUBM files, since a
full run now copies pairs that are already grouped. The implementer first
tried one vector per predicate: the base held as little, but the all-cores
peak rose to a median of 651 MB, because the freed parse buffer was never
reused. Converting in place inside the parse buffer avoided it.
