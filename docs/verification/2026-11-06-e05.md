# Verification: loop iteration 5, a full run from exact sorted batches (2026-11-06)

The change: when the canon has no class, a full run gives each predicate's
table its base tuples as one sorted batch of exact size, with the facts merged
in, instead of pushing them through the round buffer for step 0 to sort
(`1e74f80`). The kept version before it is `d21803b` (iteration 4). The
decision is iteration 5's row in `docs/specs/experiments.md`.

Raw results are in [`data/2026-11-06-e05/`](data/2026-11-06-e05/).

## Correctness

Every suite passed on the merged tree (`1e74f80`): the core library (three
new tests: a filled store starts with exact tables, filling in chunks matches
one thread, a full run starts with exact tables) and its doc tests; the CLI;
the oracle library and `minimal`, `programs`, `reference`, `w3c`,
`data_brick` and `snapshot`; the reference evaluator's library, `reference`
and `chaos`; the bench; pytest 787. Also `cargo fmt`, clippy with
`-D warnings`, and the wasm32 core. The implementer also ran the core library
and chaos with debug assertions on.

## Speed and memory

The bench at `d21803b` (before) and `1e74f80` (after), TurbOWL alone, on one
thread, the editor-size scenarios, 5 runs each, interleaved twice. Medians.
The machine was busy, not quiet.

Load average (1 min) before each set: before 1: 2.93, before 2: 2.14, after 1: 2.53, after 2: 1.95.

Reasoning on one thread fell by about 3% on the LUBM files (lubm-50 416 to
418 ms before, 403 to 404 after), from the sort and copy of step 0 that the
run no longer does. The one-thread peak fell by 5 MB, far less than the
hypothesis of 2 to 5 bytes per closure triple: the implementer's probe
showed that the round buffer at the start of a run mostly reused memory the
loader had freed. On all cores the peak fell from 617 to 577 MB in this
evaluation, but the all-cores peak has varied from 599 to 617 MB across this
week's evaluations of unchanged code, so that part is within its noise.

## Correction

By the median of the per-run peaks, as iteration 6's reviewer read them, the
all-cores peak went from 605 to 603 MB: no change. The 617 to 577 MB above
compares the largest of 3 runs, which is noise on all cores. Iteration 6's
reviewer kept the change for its speed.
