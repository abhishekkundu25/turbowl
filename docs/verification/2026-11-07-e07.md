# Verification: loop iteration 7, object indexes sorted in place (2026-11-07)

The change: a table's object index is flipped straight into one exact vector
(on the workers above the threshold) and sorted in place with
`par_sort_unstable`, with no sort buffer and no deduplication, since the flip
of distinct pairs is distinct (`f4fc0dd`). The kept version before it is
`1e74f80` (iteration 5); only records and specs changed between. The decision
is iteration 7's row in `docs/specs/experiments.md`.

Raw results are in [`data/2026-11-07-e07/`](data/2026-11-07-e07/).

## Correctness

Every suite passed on the merged tree (`f4fc0dd`): the core library (four new
tests: the in-place index equals the deduplicated sort, mapping parts matches
one thread, the debug assertion catches equal pairs, a store builds its index
in place) and its doc tests; the CLI; the oracle library and `minimal`,
`programs`, `reference`, `w3c`, `data_brick` and `snapshot`; the reference
evaluator's library, `reference` and `chaos`; the bench; pytest 787. The
implementer also ran the core library and chaos with debug assertions on.
