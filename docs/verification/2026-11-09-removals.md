# Incremental deletion implementation

Status: implemented on `feat/incremental-deletions`, acceptance open. Based on
`83b356edde2eab0809a562275d4ec9d18af139f2`.

The maintainer asked for a specification and an implementation after the small deletion
benchmark. The execution contract is in
`docs/specs/v2-3-removals.md`; tickets 22 to 24 remain the tracker.

## Implementation decisions and evidence

- Queue real base deletions, preserving the previous closure and diagnostics
  until reasoning.
  Absent and inferred-only removals are no-ops. Mixed pending changes use
  full reasoning. Pure-deletion `set_base` uses maintenance.
- DRed protects remaining base triples and axiom facts. Bounded backward
  search accepts only proofs grounded in the remaining base or axioms.
  Backward work is bounded across the whole deletion run. Failed proofs
  continue through DRed, so cycles cannot certify themselves. The final
  bounds are 1,024 steps per run, depth 64 and at most 16 candidates per
  atom. A later per-goal tuning and proof-index experiment did not reduce
  repair work and was reverted. Query-local indexes remain.
- The first implementation replayed native rule families over deletion
  deltas, then made one naive rederivation pass. Public regressions passed,
  but the small Brick comparison regressed: deletion median 3.839 ms,
  range 3.752 to 4.016 ms; full reasoning 2.157 ms, range 2.082 to 2.330 ms.
  Eleven samples per case, one warmup, load 2.71 to 2.57, approximate with
  the maintainer's earlier load exception. Class-family work alone was
  1.659 ms. Raw results: `data/2026-11-09-removals/first-maintenance.json`.
- The next implementation evaluates indexed rule-program queries for
  dependents, including helper relations, and checks rederivation at each
  overdeleted head against the survivors. This path currently requires an
  empty canon; native maintenance remains for unaffected equality classes.
  Excessive query work and unsupported builtins
  conservatively fall back to full reasoning.
- Rule parsing moved from `explain/program.rs` into `rules/program.rs`,
  with its literal rule files. Maintenance uses no explanation component;
  ordinary forward reasoning records no proof dependencies.
- Recursive helpers use tabled positive fixpoints and completed calls are
  reused within one immutable closure. Bounded query-local object indexes
  supplement native indexes. Inferred types of a changed subject may be
  overdeleted together. Conservative projections stop at the first
  ordinary-triple head and skip helpers only when every possible old head
  is already affected or protected; equality heads are never skipped.
- Pending removal limit: `clamp(base / 8, 16, 4096)`. Affected-set limit:
  `max(closure / 4, 64)`. Query work: 100,000 steps per phase. These are
  bounded heuristics, not a measured workload crossover. Threshold tuning
  remains open. Fallback preserves correctness.
- Snapshot format 3 explicitly preserves pending deletions in the change
  queue. Older formats are refused. Invalid deletion queues are checked
  at loading. Deletion queue capacity is included in held-memory counters.
- Initially, `trivial` and `literal-values` configurations use full
  reasoning. Nonempty diagnostics are recomputed, not maintained
  selectively. The positive, empty-canon path skips recomputation when
  there were no findings, because a deletion cannot create one.
  These are performance/coverage gaps, not correctness exclusions.

## Reduced regressions

Two independent review axes and the first removal chaos run found:

1. A canonical equality head protected by an explicit self-equality could
   bypass the equality fallback. Checking equality hazards before base
   protection fixes the unsupported retained merge.
2. Recomputing findings from stored representatives lost `dt-not-type`
   for an unchanged ill-typed literal hidden by an IRI representative.
   Rechecking literal members of unchanged classes restores the finding.

Both failures were reproduced in public-interface tests before fixing.
The chaos failure was removal seed 1592590853, iteration 9, default
configuration. Its reduced regression is
`an_unrelated_deletion_keeps_findings_for_literals_hidden_by_equality`.

## Small final comparison

Uses `crates/bench/examples/deletion_cost.rs`, release mode, one thread and
default switches on Brick plus small1. Each sample loads a fresh reasoner;
mutation plus reasoning is timed, with loading, initial reasoning, closure
checks and profile reads excluded. Eleven measured samples follow one
warmup per case, with order rotated. The first deletion warmup captures
process-wide rule-parser initialization; it is recorded separately from
the warmed medians. It is one startup observation, not a repeated cold
measurement. The maintainer authorized approximate timings under current load.
The measured command runs after every build and test has finished.

Measured at 2026-11-09T00:44:24.100063+00:00, macOS 27 arm64, Rust 1.99.0,
12 logical CPUs, one reasoning thread. One-minute load was 5.88
before and after; these are approximate timings under the maintainer's load
exception. No build or test from this session ran alongside the command.

| Operation | Median, ms | Min to max, ms |
|---|---:|---:|
| Unchanged reasoning | <0.001 | all <0.001 |
| Insert one fact and reason | 0.928 | 0.919 to 1.021 |
| Delete one fact and reason | 1.089 | 1.064 to 1.368 |
| Full reasoning, parsing excluded | 2.140 | 2.065 to 2.274 |

Deletion costs 50.9% of the full run, about 1.97 times faster. It does
**not** meet the phase 3 target of less than 10%. The first cold deletion warmup took
1.380 ms, stored separately from the 11 samples.
The earlier full-run deletion baseline was 1.996 ms; different machine
loads limit a direct before/after comparison.

The input has 14,817 base triples and 26,381 closure triples. The probe
adds one base fact and 49 inferred facts, for 26,431 closure triples.
Every measured and warmup result matched its complete expected triple
set. Base counts changed by exactly one for mutations; unchanged
reasoning reported zero rounds; all results had zero diagnostics.
Deletion never fell back in these samples. It overdeleted 71 facts and
queued 13 survivor-supported seeds for forward repair.
These seed counts do not include the further facts restored by forward
reasoning.

The deletion-query passes took a median 0.551 ms, while native
class-family repair took 0.464 ms. Profiled store steps took 0.006 ms.
The remaining 0.060 ms includes setup, backward checks, physical removal
and bookkeeping; those components were not
isolated. This leaves both query evaluation and repair work to reduce.

The rejected per-goal proof-budget/index probe is retained as
`proof-budget-probe.json`, with its summary and metadata. It did not
reduce the overdeletion or repair counts, so the final source uses the
simpler 1,024-step backward search. No tracing instrumentation remains.

## Open acceptance

- The final Brick deletion costs 50.9% of full reasoning, above the
  10% target.
- Removing 1,000 random facts from lubm-50 has not been measured here.
- Constant-cost deletion scaling has not been established. Physical
  removal still scans the affected predicate tables; an affected set bound
  alone does not establish a constant-time update.
- The 100,000-iteration runs per chaos shard remain outstanding. The
  regular sample does not satisfy that extended acceptance requirement.
- Initial fallback for `trivial` and `literal-values`, global recomputation
  of nonempty findings, and heuristic threshold tuning remain open.
- The exhaustive per-family alternate-proof/cascade test matrix remains
  open beyond the representative public regressions.
- The removal scoreboard and phase 3 claim are not closed. No results or
  packages were published.
